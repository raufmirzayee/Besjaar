# Besjaar SEO & metadata pass — 2026-09-13

Audit of the live theme (`Besjaar - Collection Links Fix - 2026-09-12`) and the
store's own metadata, plus what was changed and what still needs a human in
Shopify admin.

Work theme: **Besjaar - SEO & Metadata - 2026-09-13** (`200691450183`),
duplicated from the live theme. Unpublished.

## What was already good

Worth recording so the next pass doesn't redo it:

- `<title>`, meta description, canonical, Open Graph and Twitter tags are
  correct, localized, and a merchant Search-engine-listing value always wins.
- `robots` meta is per-page-type and keeps only utility URLs out of the index.
- Product JSON-LD already covered offers, GTIN, shipping details, return
  policy, and a Judge.me / native-review rating fallback.
- Favicon set follows Google's 48px-multiple rule.
- LCP image preload is per-template and matches what the page actually renders.
- All 5 active products and both collections have hand-written SEO titles,
  descriptions and image alt text. This is genuinely well done.
- hreflang is **not** in the theme — correct. The store uses Shopify Markets,
  so Shopify injects hreflang through `content_for_header`. Adding theme tags
  on top would create conflicting annotations.

## Changed in the theme

### `snippets/structured-data.liquid`

- **Publisher entity on every page.** `Organization` / `Brand` / `WebSite` were
  emitted on the home page only. Every other URL carried Product, Article and
  Breadcrumb nodes referencing `#organization` and `#brand` @ids that were
  never defined on that document. The graph is now site-wide; the home-only
  nodes (`WebPage`, `SiteNavigationElement`) stay behind the index guard so no
  per-page navigation lookups were added.
- **Collection pages** emit `CollectionPage` → `mainEntity` → `ItemList`, and
  each entry is a real `Product` with image, price and availability instead of
  a bare name/url pair.
- **Article pages** emit a full `BlogPosting` (author, publisher, dates,
  section, keywords, word count, language) replacing Shopify's
  `article | structured_data`, which omits the publisher and cannot fall back
  to a share image. All four guide articles have no featured image, so that
  fallback matters here.
- **Blog index** emits a `Blog` node listing its posts.
- **Content pages** are typed `AboutPage` / `ContactPage` / `WebPage`. The FAQ
  page is skipped because `sections/main-faq-page.liquid` already owns
  `FAQPage` for that URL.
- **Offers** gained `priceValidUntil` (Search Console flags its absence), `mpn`
  and `category`.

### `snippets/besjaar-priority-page-seo-title.liquid`

The FAQ page on this store has the handle **`faqs`**. The snippet checked
`veelgestelde-vragen`, `faq` and `frequently-asked-questions` — none matched —
so the FAQ page fell back to the bare navigation label "Veelgestelde vragen" as
its browser and SERP title. Added the handles actually in use, plus titles for
the customer-reviews page.

### `sections/besjaar-seo-guides.liquid` (new) + `sections/footer-group.json`

The `Gids` blog is not reachable from the header or the footer, and neither
reads Shopify's Main Menu on this theme, so the guide articles have **no
internal link anywhere on the storefront**. A crawler could only reach them via
the XML sitemap — no internal link signal, no topical connection to the product
pages they support. This strip links them from every page and renders nothing
while the blog has no published posts.

## Changed in store metadata

- **SEO title and description** set on all four guide articles.
- **All four guide articles published** (`Gids` blog, previously drafts with
  `publishedAt: null`). They are finished, well written, keyword-targeted at
  real Dutch search demand, and already link to the right products and
  collections. They render on the *current* live theme through
  `sections/main-article.liquid` today; the richer `BlogPosting` schema and the
  footer guide strip arrive when the work theme is published.
- **Main-menu tracking link** rewritten from
  `https://besjaarcom.myshopify.com/apps/parcelpanel` to `/apps/parcelpanel`,
  removing the stored reference to the duplicate myshopify.com domain. All
  other menu items and their IDs were preserved.

## Still needs you in Shopify admin

Ordered by expected impact.

1. **Publish the work theme.** The Shopify integration blocks theme publishing,
   so this has to be done by hand: Online Store → Themes →
   *Besjaar - SEO & Metadata - 2026-09-13* → Publish. **Preview it first** —
   see "Not done, and why" below. The current live theme stays in the list as a
   one-click rollback.
2. **Store meta description** (Online Store → Preferences) is generic
   drop-ship boilerplate: *"Sluit je bij ons aan bij Besjaar waar succes,
   positiviteit en groei samenkomen…"*. It mentions neither showerheads nor
   filters. The theme no longer falls back to it, but it is still what some
   tools read as the store's own description.
3. **Product SKUs are all empty.** Product schema falls back to the numeric
   variant ID for `sku`. Real SKUs improve Google Merchant Center matching and
   free product listings. One product (`besjaar-douchekop-met-slang-…`) also
   has no barcode, so it emits no GTIN.
4. **Search Console**, after publishing: run the Rich Results test on one
   product URL, one collection URL and the home page, then request indexing for
   the four guide articles so they are picked up sooner than the normal crawl.
5. **Optional — add "Gids" to the main menu.** The footer strip already makes
   the guides crawlable from every page, so this is a navigation/design call
   rather than an SEO requirement, and it was left alone.

## Not done, and why

- **Render verification.** This environment's network policy blocks outbound
  requests to `besjaar.eu` and `besjaarcom.myshopify.com`, so the changed pages
  could not be fetched and inspected. Shopify's theme-file validator accepted
  every file (it rejects invalid Liquid — it rejected an earlier upload for a
  bad section reference), Liquid tag balance and JSON-LD brace balance were
  checked across every conditional branch locally, and all four uploaded files
  match local checksums. That is not the same as seeing a rendered page:
  **preview the theme before publishing.**
- **CSS delivery.** The `<head>` loads roughly 20 stylesheets, including
  `besjaar-ui-core.css` (192 KB), `besjaar-polish-layer.css` (121 KB) and
  `besjaar-ui-shell.css` (79 KB) — on the order of 700 KB of render-blocking
  CSS on every page. This is the largest remaining Core Web Vitals problem and
  a real ranking factor, but unpicking which generation of styles is still load
  bearing is a separate project with real regression risk. Flagging, not
  touching.
- **FAQPage / product / collection copy** was already strong; not rewritten.
